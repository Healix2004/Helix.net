Back-End DevelopmentIntroductionHealthcare systems are becoming increasingly dependent on digital technologies to improve the quality, accuracy, and efficiency of medical services. Traditional paper-based prescriptions and manual communication between healthcare providers can lead to medication errors, delays in treatment, and difficulties in managing patient records. To address these challenges, modern healthcare applications integrate electronic medical records, intelligent decision-support systems, and secure communication between medical professionals.This project presents an AI-powered Electronic Prescription and Healthcare Management System designed to streamline the prescription and diagnostic workflow. The system enables doctors to create electronic prescriptions, automatically checks for potential drug interactions using an Artificial Intelligence (AI) service, and assists healthcare professionals in making safer clinical decisions. In addition, the system supports laboratory and radiology requests, allows specialists to upload examination results, enables pharmacists to dispense medications electronically, and provides patients with secure access to their prescriptions and medical reports.The application follows a multi-tier architecture consisting of a web portal, a backend server, an AI microservice, and a FHIR-based medical database. By integrating these components, the system ensures secure data exchange, improves patient safety, reduces medication errors, and enhances communication among doctors, pharmacists, laboratory technicians, radiologists, and patients.Overall, the proposed system aims to provide a comprehensive, secure, and intelligent healthcare platform that improves the efficiency of clinical workflows while supporting better patient care through AI-assisted medical decision-making.Back-end OverviewThe backend serves as the core component of the proposed healthcare system, responsible for managing business logic, processing client requests, communicating with the FHIR server, enforcing security policies, and coordinating interactions between different system components. It acts as an intermediary layer between the web portal used by healthcare professionals and patients and the centralized healthcare database.The backend is implemented using ASP.NET Core Web API, which provides a scalable, secure, and high-performance platform for developing RESTful services. Every request generated by the frontend is processed by the backend before interacting with the FHIR server or any external services. This architecture centralizes the application's business logic and ensures that all healthcare operations follow predefined validation and security rules./Figure ‎61.NET CorNovelty of the systemThe novelty of this project lies in combining the FHIR (Fast Healthcare Interoperability Resources) standard with Artificial Intelligence (AI) to create a smart and interoperable healthcare platform. While many healthcare systems use FHIR solely for storing and exchanging medical records, this application extends its capabilities by integrating an AI-powered clinical decision support service that analyzes electronic prescriptions for potential drug interactions before they are finalized.The system also provides a unified workflow that connects doctors, pharmacists, laboratory specialists, radiologists, and patients through a single FHIR-based platform. Medical data, including patient information, prescriptions, allergies, laboratory requests, imaging orders, and diagnostic reports, are represented using standardized FHIR resources, ensuring interoperability and seamless communication between all system components.By combining standardized healthcare data with AI-driven safety analysis, the proposed system improves patient safety, reduces medication errors, supports clinical decision-making, and enables future integration with external healthcare institutions that adopt the FHIR standard. This integration of interoperability and intelligent decision support represents the primary innovation of the proposed application.FHIR standard/Figure ‎62 FHIR standardThe application is built using the Fast Healthcare Interoperability Resources (FHIR) standard, a widely adopted healthcare data standard developed by Health Level Seven International (HL7). FHIR provides a consistent and interoperable framework for representing and exchanging healthcare information between different medical systems.In this application, FHIR is used as the foundation for managing clinical data such as patient records, prescriptions, medications, allergies, laboratory requests, radiology orders, and diagnostic results. Each type of medical information is represented as a FHIR resource, allowing the system to organize data in a standardized and structured format.By adopting FHIR, the application enables seamless communication between the web portal, backend services, AI microservice, and healthcare database. This standardized approach improves data consistency, reduces integration complexity, and allows different healthcare systems to exchange information efficiently while maintaining interoperability.Furthermore, the use of FHIR enhances the application's scalability and future compatibility with external healthcare providers, hospitals, pharmacies, and laboratory systems. Since FHIR is internationally recognized and supported by many healthcare organizations, it ensures that the system follows modern healthcare data exchange standards while promoting secure, accurate, and efficient patient care.Development tools and technologies/Figure ‎63Development tools ASP.NET Core Web API with C# as the primary programming language. Entity Framework Core was used for database access and data management. SQL Server served as the backend database.  FHIR using Firely .NET SDK to create and manipulate FHIR resources. JWT (JSON Web Tokens) ensures secure access to the system.  Swagger (OpenAPI) was used to document and test the REST APIs during development.  Visual Studio 2026 Git/GitHubSystem workflowDoctor Creates Prescription Draft/Figure ‎64 Doctor Creates Prescription DraftThe prescription creation process begins when a physician logs into the healthcare system and opens the electronic prescription page for a selected patient. The report identifies any potential drug interactions, medication conflicts, or clinical warnings that could affect the patient's treatment. At this stage, the physician must carefully review the results before the prescription can be officially approved.If the AI report identifies potential risks, the physician is encouraged to modify the prescription to eliminate these issues. This may involve replacing a medication with a safer alternative, adjusting the prescribed dosage, changing the treatment duration, or removing a medication that could cause harmful interactions. After the necessary modifications have been made, the updated prescription is submitted for another AI safety analysis. The system performs a new evaluation to verify that the identified risks have been resolved. This review-and-validation cycle may be repeated until the prescription is considered clinically safe.In certain clinical situations, however, the physician may determine that the prescribed treatment should not be modified despite the warnings generated by the AI. This decision may be appropriate when no effective alternative medication exists, when the expected therapeutic benefits outweigh the identified risks, or when the patient's condition requires immediate treatment. To support these situations, the application allows the physician to override the AI recommendation. Before the override is accepted, the physician must provide a detailed clinical justification explaining the medical reasons for proceeding with the prescription despite the reported warnings.Whenever an override is performed, the system automatically creates a complete audit record documenting the physician's decision. This audit record includes the identified safety warnings, the physician's justification, the time of the decision, and other relevant information required for medical accountability. Storing this information ensures that every override can be reviewed later by authorized personnel and provides a transparent history of all clinical decisions made within the system.After all warnings have either been resolved or appropriately justified, the physician proceeds to finalize the prescription. During this stage, the system applies a digital signature to the prescription. The digital signature verifies that the prescription has been approved by an authorized physician and guarantees that its contents cannot be altered without invalidating its authenticity. This mechanism strengthens security and protects the integrity of the prescription throughout its lifecycle.Once digitally signed, the prescription status is updated from Draft to Active, indicating that it has become an official electronic prescription. The application then generates a unique prescription identifier, allowing the prescription to be uniquely referenced throughout the healthcare system.To facilitate secure access and verification, the system also generates a unique QR code associated with the finalized prescription. The QR code allows authorized healthcare providers, such as pharmacists, to quickly retrieve the prescription information while reducing the possibility of transcription errors or fraudulent modifications. Both the prescription identifier and the QR code are securely stored together with the prescription in the FHIR-based healthcare database.After all processing has been completed successfully, the physician receives a confirmation indicating that the prescription has been finalized and is now available for the subsequent stages of the healthcare workflow. At this point, the prescription can be accessed by the patient, verified by pharmacists, and used by other authorized healthcare professionals involved in the patient's treatment.This stage represents one of the most important components of the proposed system because it combines AI-assisted clinical decision support with physician expertise. Rather than allowing artificial intelligence to make autonomous medical decisions, the application keeps the physician responsible for the final decision while ensuring that every warning is either resolved through prescription modification or documented through a justified override. By incorporating digital signatures, audit logging, unique prescription identifiers, and QR code verification, the system improves patient safety, strengthens accountability, and ensures the authenticity and traceability of every electronic prescription. Patient Access to the Electronic Prescription/Figure ‎66 Patient Access to the Electronic PrescriptionAfter the physician has completed the prescription approval process and the prescription has successfully passed all required safety checks, it becomes an official electronic prescription within the healthcare system. This resource records comprehensive information about the dispensing operation, including the medications that were dispensed, the dispensing date and time, the dispensing pharmacist, and the quantities supplied to the patient. Protecting this information is essential to preserve patient privacy, maintain data integrity, and comply with healthcare regulations. Therefore, the proposed system incorporates multiple security mechanisms to ensure that only authorized users can access healthcare resources while protecting the system from unauthorized access and data manipulation.Overall Security StrategyThe proposed system applies a layered security approach that combines authentication, authorization, encrypted communication, input validation, digital signatures, audit logging, and secure management of FHIR resources. These complementary security mechanisms work together to protect sensitive healthcare information, prevent unauthorized access, maintain data integrity, and ensure that all medical operations are performed by authenticated and authorized healthcare professionals. As a result, the system provides a secure environment for managing electronic prescriptions, diagnostic services, and patient medical records while supporting interoperability through the FHIR standard.AuthenticationThe system uses JSON Web Tokens (JWT) as the primary authentication mechanism. When a user successfully logs into the application, the backend verifies the provided credentials against the stored user's information. If the authentication process succeeds, a signed JWT access token is generated and returned to the client application.The generated token contains essential claims such as the user's unique identifier and assigned role. Every subsequent request sent by the client includes this token in the Authorization header using the Bearer authentication scheme. Before processing any request, the backend validates the token's digital signature, expiration time, issuer, and audience. Requests containing invalid, expired, or tampered tokens are rejected automatically.Using JWT authentication enables the system to remain stateless while providing secure access to protected resources without maintaining server-side sessions.Authorization/Figure ‎611AuthorizationAuthentication verifies the identity of a user, while authorization determines which resources the authenticated user is allowed to access. The proposed system implements Role-Based Access Control (RBAC) to restrict access according to each user's responsibilities.Each authenticated user is assigned one or more predefined roles, such as Doctor, Pharmacist, Laboratory Technician, Radiologist, Patient, or Administrator. Protected API endpoints are secured using role-based authorization policies implemented through ASP.NET Core Authorization attributes.For example, only physicians are permitted to create electronic prescriptions, pharmacists are authorized to dispense medications, laboratory technicians and radiologists can upload diagnostic reports, while patients are limited to viewing their own prescriptions and medical reports. This separation of responsibilities significantly reduces the risk of unauthorized access and accidental modification of medical records.Secure CommunicationAll communication between the frontend application and the backend API is performed through HTTPS. HTTPS encrypts data transmitted over the network using Transport Layer Security (TLS), preventing attackers from intercepting confidential healthcare information during transmission.Encrypted communication protects user credentials, authentication tokens, electronic prescriptions, laboratory reports, and all other sensitive healthcare data exchanged between the client and the server.Input ValidationEvery request received by the backend undergoes extensive validation before being processed. ASP.NET Core model validation ensures that all required fields are present and that submitted data follows the expected format.Additional business rule validation is also performed to verify that medical information is logically consistent before creating FHIR resources. Invalid or incomplete requests are rejected with appropriate error responses, preventing incorrect data from entering the healthcare system and reducing the risk of malicious input attacks.Digital SignaturesElectronic prescriptions are digitally signed before being finalized. The digital signature guarantees that the prescription was approved by an authorized physician and that its contents have not been modified after approval.If any alteration occurs after the prescription has been signed, the signature becomes invalid, allowing the system to detect unauthorized modifications. This mechanism strengthens prescription authenticity and improves trust between physicians, pharmacists, and patients.Audit LoggingTo ensure accountability and traceability, the system records important healthcare activities through audit logging. Critical events such as prescription overrides, medication dispensing, diagnostic report submissions, and authentication attempts are stored with timestamps and user information.Maintaining comprehensive audit records allows administrators to review system activities, investigate security incidents, and monitor user actions without affecting the original healthcare records.QR Code SecurityEach finalized electronic prescription is associated with a unique QR code. Instead of storing sensitive medical information directly inside the QR code, the system stores only a secure identifier that references the prescription within the backend database.When the QR code is scanned, the backend verifies its validity before retrieving the corresponding prescription. This design prevents unauthorized disclosure of patient information while allowing pharmacists to access authentic prescription records securely.FHIR Resource ProtectionHealthcare information is stored using standardized FHIR resources. Access to these resources is controlled exclusively through the backend API rather than allowing direct database access. The backend validates every request, verifies user permissions, and enforces security policies before any FHIR resource can be created, modified, or retrieved.This centralized access model protects patient information while ensuring that all interactions with the healthcare database comply with the application's security requirements.
